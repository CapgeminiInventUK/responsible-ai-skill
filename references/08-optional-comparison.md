# Optional supplied-package comparison
No previous package: set comparison mode Standalone, state Not requested or Previous package not supplied, and complete the core assessment. Never search for old runs or assume continuity from memory.
If supplied, validate the previous JSON against the current supported schema and its bundled baseline snapshot where available. Confirm same project with the user when uncertain. Reject malformed metadata, duplicate IDs and unsupported schema versions. A missing prior pack snapshot limits validation of previous rule results; disclose this rather than validate them against the new pack.
Record previous run ID, schema/skill/model/configuration/pack versions, comparison scope and limitations. Changed pack rules require an approved comparability decision; without it do not present control changes as like-for-like. Changed model/skill versions may explain differences unrelated to evidence.
Evidence differences: hashes support byte-level equality only when both hashes are available; same filename alone never proves unchanged content. Report added, removed, changed or uncertain evidence, not complete semantic equivalence. Control differences require stable control IDs and compatible definitions. Concern continuity requires prior IDs plus supported linkage; possible semantic matches remain proposed and require human review. Do not auto-merge or auto-close. Absence from current evidence does not resolve a prior concern; retain it as unresolved where continuity is established.
Use informational/material/critical change categories only if approved pack rules explicitly define them. Otherwise describe the difference without a rating. Comparison is a model-assisted optional step, not an implemented semantic matching engine. If it fails, record Failed or Limited comparison with reasons and provide a valid standalone current assessment. Release of core assessment does not depend on comparison.
