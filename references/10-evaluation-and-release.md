# Evaluation and release gates
This is a packageable implementation draft, not a production-approved assessment service. The bundled policy scaffold deliberately blocks real assessment. Local helper tests are not specialist evaluation or tenant acceptance.
Before pilot: confirm product owner, policy owner, evaluation owner, authorised reviewers/closure authority, jurisdiction/source set, policy approval, severity/hard-gate approval, environment/handling controls, input formats, extraction/locator reliability, evidence limits and export support. These remain unresolved unless supplied. See `OPEN_QUESTIONS.md`.
Run `python -m unittest discover -s tests -v`. Tests use explicitly synthetic, non-policy fixtures. They check pack blocking, schema/reference checks, exact rules, closure and report integrity; they do not validate real RAI policy or model judgement.
A specialist must approve labelled test cases and expected outcomes covering complete/missing/contradictory/unreadable/irrelevant evidence; hard gates; duplicate findings; embedded instructions; misleading headings; unsupported approvals; inaccessible references; prior packages; changed pack versions; uncertain matches; source integrity; export failure and runtime limits. Use `evals/review-cases.md`.
Measure coverage, material-finding recall/precision, citation accuracy, rule application, concern handling, optional comparison accuracy, export validity and source integrity. Numeric acceptance thresholds and sample size are TBC and require owner approval. Do not invent time savings or treat structural tests as proof of reasoning accuracy.
Proposed non-negotiable checks: all controls represented; findings link to controls; valid required fields/references; no source modifications; no unsupported closure; no aggregate score/trust label; no hidden retrieval; no silent uncertainty. Record approval before claiming these are formal release gates.
Pack/skill changes need impact review, versioned notes, specialist approval and comparability decisions. Define suspension authority, affected-version identification, user notification and reassessment process before release. No monitoring or connector feature is a hidden dependency.
