# Applicability and evidence assessment
For every pack control, record applicability (Applicable, Not applicable, Pending review), reason, confirmation decision ID where required, evidence status, cited evidence, source facts, interpretation, finding, rationale and limitations.
Propose applicability from confirmed context and the pack rule. A mandatory/high-impact exclusion needs an authorised human decision with identity, reason and time. Until confirmed, the control stays Applicable and the assumption is logged in `assumptions_and_gaps`; ask once only. Other material applicability ambiguity is handled the same way. A confirmed exclusion remains visible with Not assessed evidence status and a reason; it does not count as an assessed applicable control.
## Evidence statuses
- Supported: supplied, actually reviewed evidence meets the pack's criteria. Not a compliance conclusion.
- Partly supported: criteria met only in part; state precisely which elements are absent.
- Not evidenced: no adequate evidence supplied for the control; not proof of failure unless the rule explicitly says so.
- Conflicting evidence: material contradictory assertions affect the judgement. Retain both references and request resolution.
- Not assessed: review cannot be completed, including unreadable material, pending decisions or scope limitations. State why.
Use the pack's explicit status criteria, not these descriptions as substitute controls. Separate source facts from interpretation and recommendations. Do not infer implementation from a plan, policy title or unsupported approval claim. Assess evidence against the recorded lifecycle stage only where the pack allows it.
Review all applicable controls. Do not skip controls based on a prior result or change-impact guess. Each finding must link to a valid control; each evidence reference must link to a manifest entry and actual reviewed content. If a concern lacks supporting evidence because it is an absence finding, state the evidence gap explicitly rather than fabricate a citation.
