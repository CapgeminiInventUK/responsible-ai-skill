# Output, validation and export
Canonical record: `assets/assessment.template.json`, validated by `assets/schemas/assessment.schema.json` plus executable semantic checks. Report: `assets/report.template.md`, populated by the helper from that same record. Questions: `assets/open-questions.md` for paused intake and the canonical array for assessments. Never hand-maintain a second conflicting register.
## Package contents
`assessment.json` (run metadata, manifest, results, concerns/actions, decisions, questions, comparison and limitations); `assessment-report.md`; `policy-pack.json` baseline snapshot; `package-manifest.json` with SHA-256 of the other package files. Raw evidence is not included by default. The user controls saving and sharing. The ZIP is an assessment record, not a workspace update.
## Completion
Complete means processing finished, all controls have results, and no blocking questions, pending applicability or applicable Not assessed controls remain. It does not mean controls are supported, concerns are closed or approval is granted. Partial means some valid results exist but coverage/decisions remain incomplete. Failed means the assessment could not be performed or a valid package could not be produced. An intake blocked before a usable baseline should produce only the questions artefact, not a purported validated assessment.
## Checks
The helper checks JSON Schema, unique IDs, valid references, control coverage, exact rule outputs, closure evidence/human authority, applicability exceptions, question/completion consistency, project consistency and exact regenerated-report equality. It renders coverage and concern counts from canonical data, not model arithmetic. Review source citations and evidence interpretations manually; code cannot establish their truth. Check source integrity separately where original bytes are accessible.
If schema/rule/report validation fails, fix and rerun. If the runtime lacks Python/jsonschema or cannot create downloadable files, state the limitation and stop at export; do not claim executable validation. Do not silently substitute prompt-only validation. Ask for an approved runtime or output alternative. Formats/limits are local implementation choices until tested in the selected environment.
Generated records remain drafts for human review. Summarise project/time/pack, coverage, severity counts, hard gates, material questions and processing limits. No trust label, compliance certificate, deployment recommendation or model sign-off.
