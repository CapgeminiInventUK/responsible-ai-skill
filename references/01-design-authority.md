# Design authority and source reconciliation
## Source order
User's explicit bundle-format and stop/ask requirements govern packaging and interaction. The uploaded `AI_DF_Responsible_AI_Assessment_MVP_PRD_v2.0.docx`, version 2.0, 22 October 2026, governs product scope. `declarativeAgent_0.json` supplies original Digital Factory context and assessment/action-plan intent. `manifest.json` supplies original packaging identity only. No uploaded source is an approved policy pack.
## Retain
Evidence-led Responsible AI review; use-case-specific findings; linked remediation; human governance; evidence-backed closure; purpose, summary, domain/control detail, action plan, next steps, decision log and human review record.
## Replace or remove
- Original 0-5 scores, percentage weights and maturity score: replace with control-level evidence status. No aggregate score or project trust label.
- Original high-risk score-below-4 escalation: remove. Only approved pack rules can define severity and hard gates.
- Original final assurance decision / sign-off fields: replace with draft assessment conclusion, decisions required and recorded human decisions. Never imply model approval.
- Original mandatory ISO/IEC 42001, 23894, 27001, 27701, ICO and Capgemini source set: retain as candidate provenance only. The approved pack determines actual requirements, citations and jurisdiction. The uploaded agent does not supply these source texts or establish applicability.
- Original 12 domains, including monitoring: use only as candidate taxonomy, not automatically adopted controls. Reviewing supplied operational records under an approved control is distinct from live monitoring.
- Original WebSearch, OneDrive/SharePoint and People capabilities: do not port them. The MVP is manual, file-based and has no connectors or automatic policy retrieval.
- Original only-output-templates instruction: replace with MVP concise summary, structured outputs and necessary stop/ask dialogue.
## Implementation choices, not source facts
Markdown report, JSON canonical record, schema version 1.0.0 and skill version 0.1.0 are choices for this bundle. The skill runs without executable code or Python; validation is model-performed. They are not proof of compatibility with a particular Claude tenant. No policy content has been invented to make the package appear operational.
