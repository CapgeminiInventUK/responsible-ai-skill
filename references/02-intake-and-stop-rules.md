# Intake, authority and questions
Step 0 comes before intake: obtain the responsibility acknowledgement defined in SKILL.md (explicit agreement plus a typed email in valid format). It is not stored or recorded. Without it, do not perform any assessment step; record only `Not started - acknowledgement not given`.
Use `assets/intake.md`. Establish one project and explicit review purpose: Self-assessment, Second-line review or Formal assurance support. Record assessor independence as Yes, No or Not supplied; ask if it affects the review claim. Do not treat these contexts as equivalent.
Confirm user authority to upload the evidence, organisation-approved environment, classification/handling restrictions, project segregation, retention requirements and permitted output destination. No credentials are required. Until handling controls are confirmed, use only synthetic or explicitly authorised test evidence.
A project ID is user-confirmed; a generated run ID is a technical identifier, not an inferred project identity. Record UTC timestamps from the runtime. Never invent model identity, people, ownership, dates or authority.
## Blocking question protocol
This protocol applies only to hard stops: the Step 0 acknowledgement, authorisation and handling confirmation, a valid policy pack, and project identity and AI purpose. All other missing information follows the gap protocol below.
1. Record question ID, step, issue, affected controls, material effect, required answer, proposed respondent, state and resolution provenance.
2. Ask the smallest set of focused questions that resolves the blocker. Reuse explicit supplied facts.
3. Pause dependent processing. Do not decide silently. Independent inventory work may continue only when authorised and not dependent on the answer.
4. Resume only after the answer is recorded. If the user cannot answer, retain a blocked/Partial/Failed draft as appropriate, with affected controls Not assessed. Never label the assessment Complete while blocking questions remain open.
## Gap protocol (information or resources the user does not have)
Ask once. If the user says they do not have it, cannot provide it or decline, say you will proceed without it, never ask again or ask for a substitute, and add an `assumptions_and_gaps` entry: `gap_id` (GAP-01...), `type` (Gap or Assumption), a one-line `description`, `user_statement` (what the user said, briefly), `handling` (how the assessment proceeded) and `affected_control_ids`. Handling defaults: absent control evidence is Not evidenced; unknown applicability is Applicable; unknown owners/dates are TBC; unknown metadata is Not supplied; unknown review context is Self-assessment; unreadable or conflicting evidence stays Conflicting evidence or Not assessed with the reason. Keep entries brief. A gap does not by itself prevent Complete status, but any resulting Not assessed Applicable control does.
Distinguish missing intake/baseline from missing control evidence. The former blocks assessment only if it is a hard stop; the latter is a legitimate evidence status. Optional comparison absence is a disclosed standalone mode, not a blocker.
The delivered scaffold intentionally has no policy owner, jurisdiction, approved sources or controls. Do not ask the skill builder to resolve them merely to package instructions; ask the assessment user/pack owner before assessment execution.
