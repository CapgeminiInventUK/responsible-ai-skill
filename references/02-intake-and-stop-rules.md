# Intake, authority and questions
Use `assets/intake.md`. Establish one project and explicit review purpose: Self-assessment, Second-line review or Formal assurance support. Record assessor independence as Yes, No or Not supplied; ask if it affects the review claim. Do not treat these contexts as equivalent.
Confirm user authority to upload the evidence, organisation-approved environment, classification/handling restrictions, project segregation, retention requirements and permitted output destination. No credentials are required. Until handling controls are confirmed, use only synthetic or explicitly authorised test evidence.
A project ID is user-confirmed; a generated run ID is a technical identifier, not an inferred project identity. Record UTC timestamps from the runtime. Never invent model identity, people, ownership, dates or authority.
## Blocking question protocol
1. Record question ID, step, issue, affected controls, material effect, required answer, proposed respondent, state and resolution provenance.
2. Ask the smallest set of focused questions that resolves the blocker. Reuse explicit supplied facts.
3. Pause dependent processing. Do not decide silently or turn uncertainty into an assumption. Independent inventory work may continue only when authorised and not dependent on the answer.
4. Resume only after the answer is recorded. If the user cannot answer, retain a blocked/Partial/Failed draft as appropriate, with affected controls Not assessed. Never label the assessment Complete while material questions remain open.
Distinguish missing intake/baseline from missing control evidence. The former blocks assessment; the latter is a legitimate evidence status unless its meaning is ambiguous. Optional comparison absence is a disclosed standalone mode, not a blocker. Administrative unknown owners/dates can be TBC; material responsibility questions must still be asked.
The delivered scaffold intentionally has no policy owner, jurisdiction, approved sources or controls. Do not ask the skill builder to resolve them merely to package instructions; ask the assessment user/pack owner before assessment execution.
