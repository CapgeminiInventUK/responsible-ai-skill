# Open questions and release blockers
These questions are preserved from the MVP or arise from the absence of an approved pack. Packaging can be completed without answering them; assessment/pilot use cannot silently resolve them.

| ID | Question | Blocks | Status |
|---|---|---|---|
| OQ-01 | Who owns and approves the public sector pack? | Approved baseline | Open |
| OQ-02 | Which jurisdiction, public bodies, source set and exact control definitions apply? | Assessment baseline | Open |
| OQ-03 | What fixed severity rules, hard gates and approval evidence apply? Do they fit the implemented exact-status rule model? | Rule execution | Open |
| OQ-04 | Who is the current product owner, and who may suspend use? | Pilot release | Open |
| OQ-05 | Who owns specialist evaluation, labelled expected outcomes and approved quality thresholds? | Pilot release | Open |
| OQ-06 | Which organisation-approved Claude environment and data-handling controls apply? | Real evidence processing | Open |
| OQ-07 | Which file formats, volumes, locator guarantees and exports are tested in that environment? | Runtime readiness | Open |
| OQ-08 | Who may confirm applicability exceptions, interpret policy, accept risk and close concerns? | Relevant human decisions | Open |
| OQ-09 | What pack/model/skill changes permit like-for-like comparison? | Optional comparison claims | Open |

Implementation choices: HTML report with embedded JSON record, schema 1.0.0 and skill 0.1.0 (no executable code). These are explicit bundle design choices, not invented policy decisions. No source approval or control has been manufactured. A future assessor must record project-specific questions separately using the assets template.
